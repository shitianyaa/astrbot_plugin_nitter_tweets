## 分组、推送目标与历史

### 黑名单属于分组还是推送目标？

属于推送目标，以完整 UMO 为键。同一 UMO 出现在多个分组时，共用同一份作者黑名单；不同 UMO 互不影响。

目标黑名单只过滤后台分组推送。手动查询、被动链接解析和历史重推不自动套用。

### 历史重推属于分组还是推送目标？

历史记录保留原 `group_id`，重推时必须满足：

- 原分组仍存在且已启用。
- 选择的目标仍在该分组当前 `push_targets` 中。
- 未选择目标时，发送到该分组当前全部有效目标。

历史重推是显式恢复操作，不受目标作者黑名单和分组 `media_only_enabled` 限制。它会重新准备媒体，不强制仅媒体发送，并继续使用当前分组的链接和译文显示配置。

### 为什么同一条推文在不同分组还能再次推送？

seen 按 `group_id + 订阅源 + status_id` 隔离。同一条推文进入不同分组时，属于不同的去重记录。

同一分组内的多个推送目标共享这份 seen，不为每个目标单独维护 seen。

## 发送失败与 seen

### 推送目标发送失败后还会自动重试吗？

不会。推文发送接口一旦被实际调用，返回失败或发送路径抛出被调度器捕获的普通异常时，该目标都视为本轮已处理。分组内所有目标处理完成后写入 seen，下一轮不再自动发送同一批次，避免已成功目标反复收到重复推送。

失败不会计入成功数；插件会写入 `failed` 推送历史和错误原因，可在 Dashboard 的“最近推送”中手动重推。

### 哪些失败不会写 seen？

推文发送接口调用前发生的失败不会把该目标标记为已处理，例如：

- 调度器记录为“推文准备失败”的未捕获异常，例如翻译或媒体准备流程异常。
- 仅媒体模式下，媒体暂时无法准备或没有可发送候选。
- 批次概括、消息头或发送参数准备异常。
- 调度任务在发送前被取消。

这类情况会保留旧 seen/扫描水位，允许下轮重试。若同组其他目标已经收到内容，它们可能在下轮重复收到；这是保证未真正尝试发送的目标仍可恢复的取舍。

### `failed` 与 `partial_failed` 有什么区别？

- `failed`：发送结果为失败且没有可确认送达的推文。发送器报告部分失败但未提供任何已送达推文 ID 时，也按整批失败记录。
- `partial_failed`：正文或部分推文已确认送达，但媒体或批次中的其他推文未完整送达。整体发送已被接受时不要求逐条提供已送达 ID；整体失败时只记录发送器明确提供的已送达推文 ID。
- `success`：发送完成，计入成功数。

`partial_failed` 可以没有错误文本；Dashboard 会显示“部分内容未完整送达”。

### 为什么 QQ 失败后 Telegram 不再重复，但 QQ 也不自动重试？

同一分组的 seen 由全部推送目标共享。旧行为在任一目标失败时不推进 seen，会让已经成功的目标下轮再次收到相同推文。当前行为把实际发送失败视为终态，统一推进 seen；QQ 的恢复入口改为失败历史的手动重推。

## 黑名单行为

### 加入黑名单后会删除历史记录或 seen 吗？

不会。黑名单只在后台发送阶段过滤作者，不删除分组、订阅、seen、扫描水位或 push history。

黑名单命中的批次对该目标视为已处理；移出黑名单后不会自动补发此前被过滤的推文。

### 如何维护黑名单？

管理员可使用：

```text
/推文黑名单 添加 用户名
/推文黑名单 删除 用户名
/推文黑名单 查看
/推文黑名单 添加 <目标UMO> 用户名
/推文黑名单 查看 <目标UMO>
```

不填写 UMO 时使用当前会话目标。目标参数支持完整 UMO（如 `aiocqhttp:GroupMessage:123`）以及 `group:123` / `private:123` 简写；裸数字不会被视为目标，以免与数字用户名混淆。Dashboard 也可在分组的推送目标下编辑同一份目标级黑名单。

## 扫描与水位

### 为什么 Tag/List 扫描未完整时可能跳过旧积压？

达到 `html_max_pages` 仍找不到旧基准时，调度器按 `max_tweets_per_check` 处理当前候选，并在安全条件满足后用当前第一页重建基准。发送调用失败也属于已处理，因此仍可能重建基准；旧水位到当前第一页之间未扫描到的内容可能被跳过。

需要降低风险时，可提高 `html_max_pages`、缩短检查间隔，并为 `max_tweets_per_check` 设置合适的正数上限。

### 首次订阅为什么没有推送？

首次得到可用结果时只初始化 seen 和最近扫描基准，不推送历史内容。Tag/List 首轮真正为空时保持未初始化，下一次首次得到结果仍只做初始化。

## 正文、链接与日志

### `omit_status_url=false`，为什么正文里仍没有当前 Nitter 链接？

这个开关控制的是推送中是否附带原文 URL 明文。普通外部链接会在关闭时保留，但当前来源 Nitter 实例把原文改写成的同站镜像链接会始终清理，避免把镜像地址混入正文或译文。Telegram 仍会在作者头部使用 Markdown 链接到原文。

### 为什么日志里看不到每一次实例尝试？

`brief_log_enabled=true` 时，HTML 过程日志会收敛为结构化任务摘要和关键失败信息。摘要包含来源、生效实例、轮换轨迹、统计、目标成功率、warning/error 和耗时；需要逐次 `try` 或冷却跳过过程时，临时关闭简略模式即可。
